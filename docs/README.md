## 已确认的重构路线

2026-10-05 与维护者确认。按下列顺序逐项推进，每轮提交独立 PR，合并后更新进度。
继续暂停 npm 发布；保持现有公开 API、React 18/19、SSR 和多画布行为兼容。

| 顺序 | 方向               | 实施重点                                                                                                             | 状态                                                                          |
| ---- | ------------------ | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 1    | 统一编辑入口       | 将 Web Components 的插入、粘贴和选中收敛到 `api.edit()`；逐步消除固定延时和业务层的 `runAtNextTick`。                | 前六轮已合并（#336–#341）；第七轮迁移布局和圆角；其余属性与矢量命令继续迁移。 |
| 2    | 状态通知和节点快照 | 先测量 1 千、1 万节点的提交耗时、分配和 React 渲染次数，再引入提交版本、变更 ID 和共享节点索引，减少重复扫描与刷新。 | 待开始                                                                        |
| 3    | 核心 API 职责拆分  | 保留 API 入口，以组合拆出相机与坐标、导出、文档编辑等模块；先处理边界明确的功能。                                    | 待开始                                                                        |
| 4    | React 生命周期     | 提取初始化、取消、失败和销毁控制逻辑，统一状态转换，保持 StrictMode 和 SSR 懒加载行为。                              | 待开始                                                                        |
| 5    | 选择与变换交互     | 沿现有 SelectionMode 拆分移动、缩放和旋转，提取命中检测、坐标换算与手势结束逻辑。                                    | 待开始                                                                        |
| 6    | 运行时实例隔离     | 将初始化队列归属到 runtime/world，并检查 ECS 全局注册和环境适配器；有独立 App 或插件配置需求时推进。                 | 后续，优先级较低                                                              |

第一轮验收：插入和选中构成一次撤销；不依赖 100ms 延时；执行时使用最新选区和高亮；
排队操作能在取消、画布销毁时停止；粘贴和图片插入等待提交结果；两个画布互不影响。

后续约束：`edit()` 提交完成不表示渲染完成，也不提供失败回滚。确需等待渲染或清理阶段
的内部队列应保留明确语义，不做全局机械替换。状态优化需要兼容既有原地修改节点的代码，
补齐未计入历史的状态通知后才能删掉补偿刷新。交互重构持续使用桌面和移动 WebKit 回归，
涉及触摸手势变化时再补真实 iOS 验证。

第二轮验收：组合、取消组合和裁剪通过 `api.edit()` 各提交一次；命令固定触发时的
画布和目标 ID，执行时读取最新节点并跳过已删除目标；画布销毁后取消排队操作；
错误由菜单事件入口处理；验证父子关系、选区、撤销重做及多画布隔离。

第三轮验收：去背景、放大和分层在结果准备好后通过一次 `api.edit()` 插入；
不预先留下占位图，准备失败和空结果不新增历史且恢复按钮状态；固定请求时的图片、
尺寸和画布，切换选区不会改变目标，已删除或更换图片内容的源节点不接受过期结果；
画布销毁后丢弃结果；分层使用已注册的能力服务返回值，多个图层构成一次撤销。

第四轮验收：智能选区绑定画布和源图片；仅最新选点的分割结果可以显示，清空选点、
切换或替换图片、退出编辑和卸载会清理预览并丢弃过期响应；编码、分割和移除失败
均可重试；分割传入真实图片 URL，兼容 canvas 或 URL 遮罩并复制预览以避免共享。
移除时固定遮罩像素和图片，在选区仍有效时将结果放在原图旁边，通过一次 `api.edit()`
提交并支持撤销重做；不提前插入占位图，失败和空结果不新增历史。
本轮保持选点坐标规则和触摸手势不变；服务请求本身不保证可取消。

第五轮验收：文本失焦和图标字体属性补丁改用 `api.edit()`；固定触发时的画布、
目标 ID 和输入，提交时读取最新节点，跳过已删除或类型已变的目标，销毁时取消排队。
文本编辑中的隐藏仅作用于渲染实体，不写入文档和历史；未修改或清空既有文本时
恢复原内容，空白新草稿不创建节点；非空内容变更形成一次撤销，保留原始空白字符。
文本编辑器卸载丢弃活动草稿并清理监听器，重新连接后可继续编辑；重复失焦不重复提交。
图标字体补丁复制事件数据，空补丁和相同值不提交，切换面板不改变已排队命令的目标。
其余属性面板字段、矢量拓扑命令继续按组迁移；渲染专用的即时状态更新不机械改成文档提交。

第六轮验收：宽高、位置、旋转和比例锁定通过 `api.edit()` 提交；固定事件发生时
的画布、目标和数值，执行时读取最新尺寸及锁定状态，连续锁定切换按提交顺序生效。
数值输入保留小数；空值、非有限数、负尺寸和无效锁定比例在写入前跳过，未修改的
字段不捕获其他待记录变更，提交失败后输入框恢复文档值。显式设置 flex 容器尺寸
仍会关闭该轴的 hug sizing，即使数字相同也保留这次有效修改。目标删除、类型替换或画布销毁后不再提交；
验证逐次撤销重做、排队期间切换选区和画布隔离。布局、圆角及矢量命令留待后续迁移。

第七轮验收：容器布局、flex 子项与圆角通过统一的面板提交入口执行 `api.edit()`，
固定画布、目标和事件值；四边间距在提交时读取最新数组，连续修改不同边不会互相覆盖。
保留显式零值、可选布局字段清空恢复默认、单边清空归零，以及 align-self 的 Auto 语义；
空圆角输入保留原值，非法数值和选项不写入。圆角绑定固定变量键，解除绑定时解析当前
节点的变量引用、变量值及主题，缺失或不可解析的变量不产生无效圆角。
相同值和无效操作不消耗其他待记录变更；删除、类型替换或画布销毁后跳过提交，失败时
恢复控件显示并处理异常。验证各控件连线、逐次撤销、目标隔离和变量切换。
