## 已确认的重构路线

2026-10-05 与维护者确认。按下列顺序逐项推进，每轮提交独立 PR，合并后更新进度。
继续暂停 npm 发布；保持现有公开 API、React 18/19、SSR 和多画布行为兼容。

| 顺序 | 方向               | 实施重点                                                                                                             | 状态                                                                                      |
| ---- | ------------------ | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 1    | 统一编辑入口       | 将 Web Components 的插入、粘贴和选中收敛到 `api.edit()`；逐步消除固定延时和业务层的 `runAtNextTick`。                | 前十九轮已合并（#336–#350、#354、#357、#362、#364）；第二十轮图片工具会话已实现，待合并。 |
| 2    | 状态通知和节点快照 | 先测量 1 千、1 万节点的提交耗时、分配和 React 渲染次数，再引入提交版本、变更 ID 和共享节点索引，减少重复扫描与刷新。 | 待开始                                                                                    |
| 3    | 核心 API 职责拆分  | 保留 API 入口，以组合拆出相机与坐标、导出、文档编辑等模块；先处理边界明确的功能。                                    | 待开始                                                                                    |
| 4    | React 生命周期     | 提取初始化、取消、失败和销毁控制逻辑，统一状态转换，保持 StrictMode 和 SSR 懒加载行为。                              | 待开始                                                                                    |
| 5    | 选择与变换交互     | 沿现有 SelectionMode 拆分移动、缩放和旋转，提取命中检测、坐标换算与手势结束逻辑。                                    | 待开始                                                                                    |
| 6    | 运行时实例隔离     | 将初始化队列归属到 runtime/world，并检查 ECS 全局注册和环境适配器；有独立 App 或插件配置需求时推进。                 | 后续，优先级较低                                                                          |

第一轮验收：插入和选中构成一次撤销；不依赖 100ms 延时；执行时使用最新选区和高亮；
排队操作能在取消、画布销毁时停止；粘贴和图片插入等待提交结果；两个画布互不影响。

后续约束：`edit()` 提交完成不表示渲染完成，也不提供失败回滚。确需等待渲染或清理阶段
的内部队列应保留明确语义，不做全局机械替换。状态优化需要兼容既有原地修改节点的代码，
补齐未计入历史的状态通知后才能删掉补偿刷新。交互重构持续使用桌面和移动 WebKit 回归，
涉及触摸手势变化时再补真实 iOS 验证。

第二轮验收：组合、取消组合和裁剪通过 `api.edit()` 各提交一次；命令固定触发时的
画布和目标 ID，执行时读取最新节点并跳过已删除目标；画布销毁后取消排队操作；
错误由菜单事件入口处理；验证父子关系、选区、撤销重做及多画布隔离。

第三轮验收：去背景、放大和分层在结果准备好后通过一次 `api.edit()` 插入；
不预先留下占位图，准备失败和空结果不新增历史且恢复按钮状态；固定请求时的图片、
尺寸和画布，切换选区不会改变目标，已删除或更换图片内容的源节点不接受过期结果；
画布销毁后丢弃结果；分层使用已注册的能力服务返回值，多个图层构成一次撤销。

第四轮验收：智能选区绑定画布和源图片；仅最新选点的分割结果可以显示，清空选点、
切换或替换图片、退出编辑和卸载会清理预览并丢弃过期响应；编码、分割和移除失败
均可重试；分割传入真实图片 URL，兼容 canvas 或 URL 遮罩并复制预览以避免共享。
移除时固定遮罩像素和图片，在选区仍有效时将结果放在原图旁边，通过一次 `api.edit()`
提交并支持撤销重做；不提前插入占位图，失败和空结果不新增历史。
本轮保持选点坐标规则和触摸手势不变；服务请求本身不保证可取消。

第五轮验收：文本失焦和图标字体属性补丁改用 `api.edit()`；固定触发时的画布、
目标 ID 和输入，提交时读取最新节点，跳过已删除或类型已变的目标，销毁时取消排队。
文本编辑中的隐藏仅作用于渲染实体，不写入文档和历史；未修改或清空既有文本时
恢复原内容，空白新草稿不创建节点；非空内容变更形成一次撤销，保留原始空白字符。
文本编辑器卸载丢弃活动草稿并清理监听器，重新连接后可继续编辑；重复失焦不重复提交。
图标字体补丁复制事件数据，空补丁和相同值不提交，切换面板不改变已排队命令的目标。
其余属性面板字段、矢量拓扑命令继续按组迁移；渲染专用的即时状态更新不机械改成文档提交。

第六轮验收：宽高、位置、旋转和比例锁定通过 `api.edit()` 提交；固定事件发生时
的画布、目标和数值，执行时读取最新尺寸及锁定状态，连续锁定切换按提交顺序生效。
数值输入保留小数；空值、非有限数、负尺寸和无效锁定比例在写入前跳过，未修改的
字段不捕获其他待记录变更，提交失败后输入框恢复文档值。显式设置 flex 容器尺寸
仍会关闭该轴的 hug sizing，即使数字相同也保留这次有效修改。目标删除、类型替换或画布销毁后不再提交；
验证逐次撤销重做、排队期间切换选区和画布隔离。布局、圆角及矢量命令留待后续迁移。

第七轮验收：容器布局、flex 子项与圆角通过统一的面板提交入口执行 `api.edit()`，
固定画布、目标和事件值；四边间距在提交时读取最新数组，连续修改不同边不会互相覆盖。
保留显式零值、可选布局字段清空恢复默认、单边清空归零，以及 align-self 的 Auto 语义；
空圆角输入保留原值，非法数值和选项不写入。圆角绑定固定变量键，解除绑定时解析当前
节点的变量引用、变量值及主题，缺失或不可解析的变量不产生无效圆角。
相同值和无效操作不消耗其他待记录变更；删除、类型替换或画布销毁后跳过提交，失败时
恢复控件显示并处理异常。验证各控件连线、逐次撤销、目标隔离和变量切换。

第八轮验收：字体、字号、字距、行高、粗斜体、对齐和基线通过 `api.edit()` 提交，
捕获事件输入及画布和目标。对齐在执行时根据最新节点位置、文字属性和主题变量测量，
保留文本锚点与变量引用；连续对齐和基线修改按顺序生效。字号和行高支持非负数，
字距保留负值，行高零保留自动语义；清空、非法数值、无效选项和未变化的操作不提交。
三个数值字段的变量绑定固定键，解绑解析当前绑定与主题，缺失变量保持引用不变。
删除、类型替换和画布销毁后取消排队；失败后恢复控件显示，错误被事件入口处理。
验证每次有效编辑独立撤销、排队期间复用面板和事件数据、多画布隔离。

第九轮验收：顶点粘合/拆分、面切分/合并、边粘合/拆分和手柄联动通过 `api.edit()`
提交，每次有效命令形成一次撤销。拓扑命令固定画布、会话与输入，复制端点和面边界
选择；执行前检查节点、选点、工具、几何和变换仍有效，几何原地修改也会使操作失效。
关闭弹窗、断开连接或销毁画布会取消待执行操作；重复点击不重复提交。无效拓扑不记录
其他待提交变更，提交失败展示错误并恢复重试；成功提交后再关闭弹窗，避免自我取消。
手柄联动固定模式和顶点，保持连通关系有效时使用最新切线；无效、未变化和失效操作
不提交，失败后恢复选择框。仅改变临时选边偏好和工具模式的 Bend 操作保留不提交历史
的调度，避免推进无关文档变更的历史基线；底层 API 的无回滚契约保持不变。

第十轮验收：图层重命名、显示/隐藏、锁定与四种层级调整共用 `api.edit()` 命令入口，
覆盖图层面板、右键菜单与层级快捷键。提交时固定画布和目标，执行时读取最新状态及
同级顺序，连续切换各自形成一次撤销；图层行按钮不会额外触发行选择和历史提交。
删除、类型替换或画布销毁后跳过提交，到达层级边界、名称未变化和已锁定的重命名
不记录其他待提交修改。重命名保留输入空白；Escape、输入框移除或复用会丢弃草稿，
Enter 和失焦只提交一次，提交失败可重新编辑。已接受的命令保留原画布和目标归属。
后续继续处理图层拖动换父级、删除、剪切与键盘位移，再推进其他属性及性能基线。

第十一轮验收：图层拖动排序/换父级、面板删除、原生 Backspace 和四向键盘位移通过
`api.edit()` 提交，固定画布与目标，读取执行时的最新状态；每次有效命令独立撤销。
拖动先恢复 Sortable 移动的 DOM，再验证父级、同级成员、节点锁定与祖先环，验证后
一次写入父级、平移和顺序；失败不留下部分换父级。图层列表之间跨画布拖动被拒绝，未变化的排序
不提交。保留原有平移累加的换父级语义，旋转/缩放父级的完整仿射补偿仍是后续工作。
删除整组包含后代，只选择实际存活的下一图层，并保留排队期间用户选择的其他图层。
剪切在事件派发时同步写入剪贴板数据，菜单剪切等待系统复制成功后再排队删除；复制
失败、画布销毁，以及复制期间目标或后代发生变化时保留文档，不消耗其他待记录修改。
原生与 React 快捷键的事件归属保持分离；后续继续填充、描边及效果等属性迁移。

第十二轮验收：填充与描边快捷色盘的颜色、透明度、变量绑定和解绑通过同一 `api.edit()`
入口提交，固定触发时的画布、目标和输入。执行时读取第一层的最新属性，保留其他绘制层，
描边直接读写 `strokes`，不再依赖已废弃的 `stroke` / `strokeOpacity` 字段。
连续事件按顺序提交并独立撤销；保留零透明度、变量引用以及图片的 fit/position 设置。
解绑读取最新变量和主题；无效数值、缺失变量、无变化以及失效目标在写入前取消，
不捕获其他待记录修改；画布销毁取消排队，提交异常可重试。
本轮保持取色器逐事件提交的行为，连续拖动合并为单次手势历史另行设计；
属性面板的多层增删、描边几何和效果面板继续按组迁移。

第十三轮验收：属性面板的填充/描边层添加、移除、显隐、颜色、透明度和透明度变量
与快捷色盘共用 `api.edit()`。行操作绑定触发时的绘制层对象，连续修改延续其逻辑身份；
前面的层被移除、或保留对象的数组换序后仍能找到原层，相同颜色的不同层不会混淆。
重复移除及已移除层的后续编辑不误改下一层；外部替换层对象、导入或撤销造成旧对象
失效时取消旧命令。身份仅存于以 API 为键的弱映射，不向文档添加 ID 或其他元数据。
添加读取提交时的完整数组，连续添加不覆盖；每个有效事件独立撤销。行透明度支持
小数及零值，空值、非法数值和无变化不提交，控件刷新时恢复文档值；变量绑定保留
引用，解绑读取最新主题与变量。面板复用不改变已接受命令的归属，读取绘制层不修改
文档。后续继续描边几何、效果及绘图设置；本轮不新增绘制层排序 UI。

第十四轮验收：描边宽度、实线/虚线、虚线长度和间隔、对齐、端帽、连接、起止标记及
宽度变量通过 `api.edit()` 提交，固定触发时的画布、节点和输入。虚线长度与间隔在执行时
读取最新的另一半数值，连续切换线型或修改两项不会互相覆盖，各有效事件独立撤销。
宽度保留小数及零值，虚线长度和间隔必须为有限正数；非法输入、未知选项、与当前状态
等价的默认值和重复选择在写入前取消，不捕获其他待记录修改。变量绑定保留引用，解绑读取
最新变量与主题，缺失或无效结果不写入。控件从文档恢复显示值；目标锁定、删除或类型
变化时取消，画布销毁取消排队，提交异常可重试。后续继续效果、混合模式和绘图设置。

第十五轮验收：效果面板的添加、删除、排序、类型、参数及渐变颜色操作与节点混合模式
统一通过 `api.edit()` 提交。滤镜和颜色使用仅存于当前画布的行标识，连续修改读取提交时
的参数与区间另一端，重复删除不会错删相邻行；外部替换滤镜后取消旧行操作，不向文档
增加标识字段。多选先检查全部目标，一次有效操作形成一条撤销记录，mixed 状态连续添加
只在第一次统一内容。空操作与无效输入不捕获其他待记录修改，锁定、删除、类型变化或
销毁时取消，失败后控件恢复且可重试。同时修复最底层图形使用混合模式时背景尚未初始化
就被读取，导致渲染和后续编辑停滞的问题。后续继续绘图设置等属性迁移；仍不发布 npm。

对象吸附修复验收：优先响应 lesson-027 的拖动与缩放问题，移动使用指针起点和原始位移，
不把吸附后的显示位置作为下次计算起点；对象吸附独立于像素网格，阈值按 CSS 屏幕像素
换算。缩放对移动的边或角计算吸附，保留比例、居中、旋转、多选和触摸偏移；排除选区
祖先与后代及隐藏、视口外参考对象，结束或 Escape 清除辅助线。保留拖动等间距，并明确
缩放间距、等尺寸和绘制吸附仍待实现。小图形边缘命中优先于附近的旋转环。

多选旋转修复验收：固定手势起始几何，显示选框和锚点随当前旋转变换更新；松手后刷新
最终包围盒，保留自定义旋转中心的世界坐标。检查正反向旋转、角度跨越、连续操作、
Escape、撤销重做和 WebKit 触摸旋转。

翻转修复验收：lesson-021 的 resize 使用按下时固定的选框与手柄身份，跨过对边后保留
有符号的尺寸，避免丢失镜像或让固定对角漂移。旋转和缩放符号来自同一次矩阵分解；
路径、折线和矢量网络仅烘焙未保留在 Transform 中的部分，避免重复翻转。覆盖四边四角、
双轴翻转、零尺寸穿越、Shift/Alt、已翻转节点、多选、翻转后旋转、单步撤销重做、渐变像素
及 WebKit 触摸翻转。中英文教程说明默认开关，交互示例开启翻转并使用渐变展示方向。

翻转后的尺寸标签修复：合并宽高与已有的 `scaleX` / `scaleY` 后归一化选框局部边界，
在屏幕坐标中选择朝下的外侧边，
标签沿边缘法线保持 8px 间距，不随缩放改变。计算包含图形旋转和相机旋转，CSS 以边缘
锚点定位，避免翻转或旋转后标签覆盖图形；线段标签保持居中并沿屏幕中的线段方向显示。
验证跨零、横向/纵向/双轴翻转、翻转回拖及继续缩放，覆盖 Chromium 和 WebKit。

ECS 文本缩放修复：字号和换行重排后的实际尺寸与拖拽目标框不完全相等，按实际测量结果
补偿节点位置，固定对向角、对边中点或 Alt 缩放中心；基线和对齐偏移在文本局部坐标中
重新归零。拖动与松手后均使用实际文本边界，避免换行预览框切换时跳动；纯旋转保留
字号和排版。回归覆盖四角四边、六种基线、旋转、镜像、父级与相机变换、重复拖动、
翻转回拖、比例锁定、触摸及撤销重做，保留 atlas 复用检查。多选文本的重排策略不在本轮
扩展；完成此修复后继续第十八轮之后的编辑入口重构，仍不发布 npm。

第十六轮验收：形状、铅笔、笔刷和文本的绘图默认设置共用同步偏好更新入口，不调用
`record()` 或 `edit()`，避免捕获尚未提交的文档修改或推进其历史基线，保留撤销重做分支。
偏好在事件发生时更新对应画布与工具，读取最新设置；相同值和无效输入不写入，断开连接
或画布销毁后的事件无效，失败后控件恢复且可重试。数值保留小数与合法零值，颜色与透明度
直接读写第一层 `fills` / `strokes` 并保留其余层；兼容旧描边偏好，读取不原地修改状态。
