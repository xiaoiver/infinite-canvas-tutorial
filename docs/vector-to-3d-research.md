# 2D 矢量图形挤出为 3D：调研与推进计划

调研日期：2026-10-15。目标是让画布上的闭合 Path，以及导入 SVG 中可表示为闭合填充轮廓的图形，保留可编辑的 2D 源节点，并实时生成可选择、可旋转的 3D 网格。

## 实施进度（2026-10-18）

以下的“调研基线”和“原定计划”保留了实施前的判断；实际实现以本节和 [Lesson 39](../packages/site/docs/guide/lesson-039.md) 为准。

-   闭合 Path 与 SVG 的填充轮廓已经接入 `Extrude3D`。封盖、孔洞、侧壁、倒角、侧面颜色、编辑后的网格同步和 GLB 导出均已实现。矩形、圆角矩形、圆与椭圆、闭合多边形及部分闭合折线可作为 SVG 输入；分组、`use` / `symbol`、`viewBox`、局部 `clip-path` 与部分变换也已有覆盖。
-   App 已提供 SVG 导入为 3D、Path / 矩形挤出参数和 GLB 导出。每个画布会创建与 2D 视图联动的 `Camera3D`。交互示例、ECS 测试和 App 风格的浏览器回归已加入。
-   描边转实体、文字挤出、渐变/图案材质、遮罩、滤镜及外部引用仍不在已支持范围。后续重点是实际 SVG 素材的兼容性、复杂素材性能，以及部署后 App 的人工验收。

## 调研结论

社区方案大致分为两类，产物和交互能力不同：

| 方案             | 代表实现与证据                                                                                                                                                                                                                                                                                                      | 对本项目的启发                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 2D 立体视觉效果  | 开源 [Shape Extrude](https://github.com/misa-r/figma-extrude-plugin/blob/main/code.js) 克隆前后矢量轮廓，用偏移的四边形连接边缘，最后合并为 Figma 矢量。                                                                                                                                                            | 适合保持纯 2D 可编辑图层，但没有真正的深度、背面、三维光照或网格导出。                         |
| 真 3D 网格       | [Vector to 3D](https://pissang1.gumroad.com/l/figma-plugin-vector-to-3d) 将矢量/文字转为 3D 模型，提供材质、灯光、布尔/SDF 组合和 GLB 导出；开源 [Vecto3d](https://github.com/lakshaybhushan/vecto3d/blob/main/components/previews/svg-model.tsx) 使用 `SVGLoader`、`ShapePath.toShapes()` 和 Three.js 的挤出几何。 | 用户流程通常是导入/选择图形 → 调深度与倒角 → 调材质和视角 → 导出。网格几何和渲染可以分层实现。 |
| 原矢量持续可编辑 | [Spline Pen Tool](https://docs.spline.design/designing-in-3-d/objects/pen-tool) 可以编辑矢量轮廓，再给形状设置挤出与倒角；[2D 对象挤出](https://docs.spline.design/designing-in-3-d/objects/extruding-2d-objects-in-3-d) 使用形状面板的 Extrusion 属性。                                                            | 挤出应当是源节点的参数化属性，而不是一次性的破坏性转换。                                       |

[Three.js `ExtrudeGeometry`](https://threejs.org/docs/pages/ExtrudeGeometry.html) 提供深度、曲线细分和倒角等参数，是几何行为的参考实现，不要求把 Three.js 加入 ECS 运行时。它的 `extrudePath` 指沿 3D 曲线挤出，与本计划沿画布 Z 轴生成厚度是不同功能。

完整 SVG 导入本身也有边界。[Spline 官方文档](https://docs.spline.design/importing-content/how-to-import-content)标明 SVG 仅部分支持，并提醒清理重复点与开放路径。因此首版按可验证的 SVG 子集交付，遇到不可挤出的节点应给出原因，保留其 2D 显示。

## 调研基线（实施前）

-   `Extrude3D` 已保存 `depth`、`z`、三维 `rotation`，并由 `EnsureExtrudeMeshes`、`SyncExtrude3D` 管理伴生 `Mesh3D`；3D 渲染、光照、拾取和 gizmo 已有基础。参见 [`Extrude3D.ts`](../packages/ecs/src/components/geometry3d/Extrude3D.ts)、[`EnsureExtrudeMeshes.ts`](../packages/ecs/src/systems/EnsureExtrudeMeshes.ts) 和 [lesson-039](../packages/site/docs/guide/lesson-039.md)。
-   目前 `extrude3d` 只属于序列化的 `rect`；伴生几何固定为单位立方体，圆角矩形也不会生成对应轮廓。参见 [`serialized-node.ts`](../packages/ecs/src/types/serialized-node.ts)、[`unit-cube.ts`](../packages/ecs/src/utils/geometry3d/unit-cube.ts)。
-   Path 已有自适应曲线采样、`evenodd`/`nonzero` 填充规则和 Earcut/libtess 填充三角化；SVG 可导入为画布节点。参见 [`path-rendering.ts`](../packages/ecs/src/utils/path-rendering.ts)、[`path-fill-mesh.ts`](../packages/ecs/src/utils/path-fill-mesh.ts)、[`ImportSVG.ts`](../packages/ecs/src/commands/ImportSVG.ts)。
-   现有 `tessy.ts` 只返回封盖三角形。侧壁还需要填充区域的**真实边界**；直接连接原始 Path 子路径会在孔洞、重叠轮廓和自相交处产生错误面。
-   `shouldSuppress2DShapeRender` 只要实体带 `Extrude3D` 就隐藏 2D 绘制。扩展到 Path 时，应验证伴生网格就绪与几何生成失败时的显示策略，避免图形暂时消失。

## 原定首版范围与用户流程

1. 用户选中闭合、具有填充的 Path，执行“挤出为 3D”，调整 `depth`、`z`、三维旋转；修改原 Path 锚点后，网格随之更新。原节点保留其 id、层级、序列化数据和撤销历史。
2. SVG 入口复用现有导入流程。首批支持可转换为闭合填充轮廓的 `path`、`polygon`、`rect`、`circle`、`ellipse`；多图形 SVG 按原图层分别挤出，保留各自的颜色和分组，不自动把相交图形布尔合并。
3. 正确处理一个 Path 内的多个轮廓、孔洞、`evenodd`/`nonzero`、曲线和不相连区域。默认使用源节点的首个纯色填充作为 3D 基础色，与现有矩形挤出规则一致。
4. 开放路径、仅描边图形、文字、渐变/图案填充、遮罩、裁剪路径和滤镜先保持 2D 原样，并显示明确的不可挤出原因。导入 SVG 的实际语义需逐项核对；不把“SVG 可导入”等同于“所有 SVG 效果可挤出”。
5. 首版为直侧壁、无倒角的真 3D 网格。倒角、独立前/侧面材质、复杂布尔组合和 GLB 导出另列后续阶段。

## 几何与 ECS 设计

### 一个填充拓扑，两类表面

输入应为 Path 局部坐标中的闭合轮廓、`fillRule` 和可控的曲线误差。先去除相邻重复点、零长度边及无效数值，再用现有自适应采样得到折线。首次实现应采用稳定的局部几何精度，避免仅因画布缩放就不断重建 3D 缓冲；画质与网格规模通过实际示例测量。

必须先按 `fillRule` 解析哪些区域属于实体。当前使用的 libtess 支持 `GLU_TESS_BOUNDARY_ONLY`，可返回区分外轮廓与孔洞方向的闭合边界，见 [GLU 属性说明](https://learn.microsoft.com/en-us/windows/win32/opengl/glutessproperty)。建议先用一个独立几何验证确定其在本项目的自相交与嵌套轮廓输入上是否可靠，然后从**同一规范化填充区域**生成：

-   前、后封盖：三角化填充区域；正反面法线与索引绕序一致。
-   外边界及孔洞侧壁：沿边界边生成四边形，按轮廓方向计算朝外法线；跳过内部共享边。
-   UV：封盖使用平面坐标，侧壁使用累计边长与深度；检查翻转、负缩放与孔洞方向。

任何边界解析失败、过度复杂或退化的输入应拒绝此次挤出并报告原因。不要生成不封闭的网格，也不要用源图形的包围盒替代实际轮廓。

### 接入现有组件

-   将 `extrude3d` 以兼容方式扩展到 `PathSerializedNode`。保留现有 `rect` 数据和默认值；几何生成按源图形类型分流，矩形原有回归必须继续通过。
-   沿用源实体 → 伴生 `Mesh3D` 的关系，以及画布作用域、材质同步、3D 拾取和 gizmo。网格归一化或变换接入时，要核对 Path 自身的局部坐标、父级变换、旋转、翻转与非等比缩放；现有矩形仅依赖 bounds 的变换不能直接假定适用于所有 Path。
-   仅在 `d`、`fillRule`、几何精度或影响轮廓的属性变化时重建网格。平移、普通旋转、材质与相机变化复用几何和 GPU 缓冲。限定缓存规模，并在源删除、类型替换、撤销与画布销毁时释放伴生资源。
-   原 2D 图形与 3D 伴生网格之间的显隐切换必须有就绪条件；几何构建失败或尚未完成时仍能看到源图形。避免以固定延时协调 ECS 写入和渲染。

## 原定分阶段 PR 计划

| 阶段              | 独立 PR 的产出                                                                       | 验收条件                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| A：拓扑与几何     | 纯函数轮廓规范化及无倒角挤出网格生成器，不接入编辑器。                               | 方形、曲线、两个分离区域、孔洞、嵌套孔洞、两种填充规则、自相交与退化输入的封盖/侧壁结果一致；检查法线、绕序、有限数值和闭合边。 |
| B：Path 接入      | `PathSerializedNode.extrude3d`、伴生网格创建/更新/清理、选中与 gizmo、显隐就绪策略。 | 原 Path 修改、变换、撤销重做、删除与多画布隔离正确；现有 rect 挤出不回归；静止帧和仅变换时不重建几何。                          |
| C：SVG 与示例     | 导入 SVG 后的批量挤出入口、参数面板、交互示例和中英文文档。                          | 常见图标与 logo 的多图形、颜色、分组、孔洞和继承变换正确；不支持节点有可读提示；桌面及移动端可操作。                            |
| D：视觉与交换格式 | 倒角、独立面材质、必要的网格导出能力，在前三阶段稳定后分别评估。                     | 倒角不会封住孔洞或自交；导出与应用内网格方向、材质和尺寸一致。先确认格式需求，再决定 GLB 的具体工作量。                         |

每阶段仅运行与变更相关的单元、真实渲染和浏览器回归；几何阶段另加固定输入性能基线。使用一个约千段的复杂 SVG 和重复实例测量 CPU 构建耗时、顶点数及编辑后的更新次数，再据数据决定是否需要 Worker 或分级精度。完整 ECS 覆盖率仍按仓库既有口径报告。

## 后续验证重点

1. 对真实图标与 logo 建立导入、编辑、导出的兼容性样本，按使用频率决定描边转实体和更多 SVG 效果的优先级。
2. 为复杂 SVG 和重复实例测量构建耗时、顶点数、编辑后的更新次数与内存占用，再决定是否需要 Worker 或精度分级。
3. 在已部署的 App 中人工验证导入、编辑和 GLB 下载全过程，并记录不同浏览器的差异。浏览器回归覆盖了同类代码路径，但不替代部署环境验收。
