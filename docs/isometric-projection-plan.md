# 等距投影：现状、设计与实施计划

调研日期：2026-10-19。目标是在现有 ECS 3D 渲染器中提供可编辑的等距视图，并在后续阶段让它与无限画布的导航和矢量挤出流程协作。此文是实现计划，不改变当前相机行为。

## 参考效果与术语

[Anatomy Collection](https://skills.wheresryan.sh/anatomy/collection#webgl) 展示可以转动和交互的轴测图。[作者的实现说明](https://skills.wheresryan.sh/anatomy/how-i-built-it)指出：机械主体由投影后的 SVG 图形绘制，WebGL 叠层负责火焰、水、光等动态效果。其默认视角为方位角 45°、俯角 30°，视觉上是常见的 2:1 **二轴测视角**；三轴等比例的严格等距视角俯角约为 `atan(1 / sqrt(2)) = 35.264°`。

本项目已有真正的 3D Mesh、SVG/Path 挤出、深度测试、PBR 光照和阴影。因此相机视角可以直接作用于几何，无需把 3D 场景预先烘焙成 SVG。要达到参考站的精密插画风格，还需要专门的材质、轮廓、标签、动画和效果设计；这些是视角之外的工作。

## 当前实现与缺口

-   [`Camera3D`](../packages/ecs/src/components/geometry3d/Camera3D.ts) 已提供 `projection: 'orthographic'`、`eye`、`center` 和 `up`。自由相机在 [`buildCamera3DSceneUniforms`](../packages/ecs/src/utils/mesh3d-scene.ts) 中使用 `lookAt`；渲染、拾取和 gizmo 共用这组矩阵。
-   现有“linked + orthographic”直接使用 2D 画布的顶视投影，不读取倾斜的 `eye`；[`CameraSync`](../packages/ecs/src/systems/CameraSync.ts) 也会将联动相机保持在正面朝向。因此仅修改 `eye` 不会使当前的联动示例变为等距视图。
-   自由正交相机的可见高度目前由 `abs(eye.z - center.z)` 推出。转动视角时这个值会变化，使构图意外缩放；需要与相机距离、俯角解耦的正交视图高度。
-   声明式 [`camera3d` 配置](../packages/ecs/src/types/serialized-node.ts) 只有 `linked`、`projection`、`clearColor`，不能设置相机姿态或视图高度。当前相机由第一个 `mesh3d` 节点创建；多 Mesh 场景需要明确的画布级相机归属。
-   2D 图形在屏幕平面上编辑，挤出后的 Mesh 在 3D 世界中。倾斜相机下，两者不再具有相同的屏幕坐标；不能沿用顶视模式中的命中位置和手柄换算。

## 相机与坐标契约

“等距”作为**正交相机预设**提供，底层仍使用现有 `orthographic` 投影。首批预设：

| 预设       | 方位角 |    俯角 | 用途                        |
| ---------- | -----: | ------: | --------------------------- |
| 严格等距   |    45° | 35.264° | 三个世界轴具有相同屏幕比例  |
| 2:1 二轴测 |    45° |     30° | 接近 Anatomy 默认的插画构图 |

采用 Z 向上的世界空间，`eye = center + distance × [cos(elevation) cos(azimuth), cos(elevation) sin(azimuth), sin(elevation)]`，`up = [0, 0, 1]`。正交视图高度单独决定屏幕比例，不随 `distance` 或旋转改变。既有 `projection: 'orthographic'`、顶视联动和未设置预设的序列化数据继续保持原语义。预设是初始参数；用户可随后自由调节方位角、俯角和缩放。

第一阶段只将 Mesh、挤出后的 Path/SVG、3D gizmo 和地板放入等距相机。现有伴生 Mesh 在联动模式中沿用画布的 Y 向下坐标；接入自由相机前，需要在同一个源到世界变换中处理 Y 轴与挤出 Z 轴，渲染、拾取和导出必须共享结果。2D 源图形仍在原始 2D 编辑视图中修改；切换视图后网格依照现有源到伴生 Mesh 的同步机制更新。标签和控件保持屏幕朝向。第二阶段再为等距视图增加画布导航和地面平面定位；不能直接把旧的 2D 矩阵套到倾斜视图上。

## 分阶段交付

| 阶段                    | 实现                                                                                                                                 | 验收                                                                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| A：可展示的等距 3D 视图 | 增加画布级正交相机视图高度及等距/2:1 预设；声明式入口转发相机配置；提供立方体、挤出 Path/SVG、地板和光照的交互示例与中英文文档。     | 平行边无透视汇聚；三个轴的长度在严格等距预设下相等；切换预设和调视图高度无意外缩放；多画布互不影响；旧 `Cube` 示例和旧 JSON 保持原状。 |
| B：导航与编辑           | 在等距视图中提供平移、缩放和可约束的视角转动；用渲染同一矩阵生成拾取射线，将指针投到地面或指定编辑平面；同步 gizmo、选框及屏幕标签。 | 拖动画布、滚轮缩放和窗口尺寸变化后所见与所选一致；旋转/平移/缩放 Mesh 与挤出图形不漂移；鼠标、触摸及触控笔可操作；不会误改 2D 源轮廓。 |
| C：插画式表现           | 在核心相机与交互稳定后，增加可选轮廓、平面色阶、标注锚点及针对选定场景的 WebGL 效果示例。                                            | 标注跟随 3D 锚点且保持可读；效果在主几何前后遮挡正确；关闭特效后主体仍可理解；低性能设备可以关闭效果。                                 |

阶段 A 采用单一画布相机作为视图状态，不让后插入的 Mesh 静默覆盖相机。相机配置变化只更新矩阵和相关 uniform，不重建 Mesh 几何。阶段 B 将 2D 编辑与等距预览的切换做成可观察的视图状态，并明确相机操作是否进入撤销历史；不借助固定延时等待 ECS 同步。

## 实施进度（2026-10-24）

-   阶段 A 已在 [#527](https://github.com/xiaoiver/infinite-canvas-tutorial/pull/527) 完成：相机预设、独立视图高度和双语示例。
-   阶段 B 的导航基础已在 [#528](https://github.com/xiaoiver/infinite-canvas-tutorial/pull/528) 完成：拖动平移、受限俯角旋转、地面锚点缩放，以及双指手势。相机手势属于视图状态，不进入文档撤销历史。
-   [#529](https://github.com/xiaoiver/infinite-canvas-tutorial/pull/529) 已完成倾斜视图的反向深度拾取、3D 按下优先级与屏幕朝向的名称标签。
-   [#530](https://github.com/xiaoiver/infinite-canvas-tutorial/pull/530) 已完成按 Mesh 屏幕投影范围进行实时框选，并支持 Shift 从地板上开始框选。
-   [#531](https://github.com/xiaoiver/infinite-canvas-tutorial/pull/531) 已完成指定 Z 编辑平面上的直接盒子绘制及双向投影 API。
-   [#532](https://github.com/xiaoiver/infinite-canvas-tutorial/pull/532) 已让等距视图直接编辑挤出 Path/SVG 的外轮廓和孔洞锚点；[#533](https://github.com/xiaoiver/infinite-canvas-tutorial/pull/533) 扩展到施加 3D 旋转和父级剪切的情况。
-   [#534](https://github.com/xiaoiver/infinite-canvas-tutorial/pull/534) 提供触屏可用的独立视角旋转工具。
-   [#541](https://github.com/xiaoiver/infinite-canvas-tutorial/pull/541) 将多选 Mesh/挤出图形的 Gizmo 合并为选区中心的一个手柄，平移和旋转使用同一撤销步骤。本轮补充共同旋转以及拖动时切换选区的回归；多选缩放尚未实现。
-   触摸与触控笔验收覆盖文档中的共用 Gizmo 和 SVG 锚点：移动 Chromium 使用可信触摸/触控笔手势，移动 WebKit 使用原生触摸点击与触摸指针事件拖动。SVG 锚点层阻止页面触摸手势抢占拖动；iOS Safari 真机仍需验收。
-   阶段 C 首轮加入可关闭的 3D 锚定标注：立方体标签取实时 Mesh 中心，挤出 SVG 标签取可编辑 Path 顶点。随相机和轮廓变化更新，屏幕外标注隐藏。标注位于 SVG 覆盖层，不参与深度遮挡；轮廓线、平面色阶和 WebGL 效果仍待实现。
-   当前以固定的等距/二轴测场景验证 Mesh 与挤出 Path 的可见性、光照/阴影和相机变化时的网格上传。阶段 B 完成后，再推进阶段 C 的可选轮廓、标注与效果示例。

## 测试与性能门槛

1. 相机纯函数测试覆盖两种预设、轴投影比例、边缘输入、缩放、宽高比、旧配置兼容；统一矩阵用于渲染、拾取和 gizmo。
2. ECS 交互测试覆盖源 Path 改动后的伴生 Mesh、深度遮挡、点击前后重叠物体、负缩放与多画布隔离；浏览器中检查桌面和 iOS 触摸手势。
3. 视觉回归固定典型等距场景及其变焦后的截图，同时检查方向光/聚光灯阴影和环境光在倾斜视角下的表现。
4. 用包含多个挤出 SVG 的场景记录相机拖动时的帧耗时与几何上传次数。纯相机操作不得触发挤出网格重建。

首个实现 PR 应完成阶段 A，再依据浏览器验收拆分 B、C。阶段 A 的示例和文档将明确说明当前是否支持等距视图下的直接 2D 锚点编辑。
